## 接到真實商品時

初始資料在 `assets/catalog-data.js` 的 `products`；每款 `variants` 有獨立的 250g／500g 售價和庫存包數。`batches` 包含烘焙日期、秒數和包裝量。商品與批次以 ID 關聯，請保留模型驗證規則。圖片在 `gallery`；英文文案同步更新 `assets/en-dictionary.js`。正式確認商品時可把 `placeholder` 改為 false；不要因此自動移除整站的展示交易說明，因為付款、登入、資料庫仍未串接。

後台可以編輯商品、圖片、風味、價格、上下架，庫存另從庫存管理調整，烘焙從批次流程處理。已存在訂單的商品不要更換 ID 或刪除，以免失去歷史關聯。修改售價不改寫舊訂單價格。

瀏覽器保存的內容優先於種子資料。更換來源檔後，既有使用者可先匯出 JSON 備份，再透過後台編輯／匯入，或在確認只需示範資料時重設；不可偷偷清除 localStorage 來讓畫面看似更新。
